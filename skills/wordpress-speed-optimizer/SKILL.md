# WordPress Speed Optimizer

PSI מחזיר שני דברים שונים באותה תשובה, והם חלוקים כמעט תמיד:

| | מה זה | מה הוא שווה |
|---|---|---|
| **שדה (CrUX)** | מה משתמשי כרום באמת מדדו ב-28 יום | זה מה שגוגל מדרג לפיו |
| **מעבדה (Lighthouse)** | סימולציה על חיבור מוחנק | טוב לאבחון סיבות, לא למסקנות |

**השדה קובע אם יש בעיה. המעבדה קובעת מה גורם לה.** דף עם ציון 38 ונתוני שדה
ירוקים הוא לא שריפה, והזדמנות של 2 שניות על מטריקה שעוברת בשדה לא מקבלת
מקום ראשון — גם אם התיקון שלה קל. למטריקה שעוברת אין יותר מה להרוויח.

## מה הסקיל לא עושה

**לא כותב לאתר.** כמעט כל תיקון מהירות הוא הגדרה בתוסף cache, בשרת או במדיה
— אין לזה REST endpoint בטוח, ו"אופטימיזציה" אוטומטית היא הדרך המהירה ביותר
לשבור עיצוב. מה שכן אוטומטי: האבחון, התעדוף, פקודת העבודה, והאימות אחריה.

## תהליך העבודה

### שלב 0: בדיקת תקינות

```bash
python scripts/speed_optimizer.py --self-check --client example.com
```

### שלב 1: מדידה

```bash
python scripts/speed_optimizer.py --mode analyze --client example.com \
    --url https://example.com/services --live
```

`--live` מריץ PSI על מובייל ודסקטופ ושומר את התשובה הגולמית — היא הופכת
לבסיס ההשוואה בהמשך. אין מפתח? עובד, אבל נחסם מהר; הוסף `PAGESPEED_API_KEY`.
יש כבר תשובה שמורה: `--psi-data psi.json`.

**מובייל חובה.** קובץ בלי מובייל נדחה — גוגל מדרג לפי מובייל, ודסקטופ לבדו
לא עונה על השאלה.

### שלב 2: הדוח

```
═══════════════════════════════════════════════════════
  ⚡ מהירות — example.com
═══════════════════════════════════════════════════════
  דף                          https://example.com/services
  שדה (מובייל)                LCP 4200ms · INP 180ms · CLS 0.050
  מעבדה (מובייל)              ציון 42 · LCP 4600ms · TBT 520ms
  חיסכון צפוי                 1,420ms
───────────────────────────────────────────────────────
[21:04:11] ⚠️  נכשל בשדה ב-LCP — זה מה שגוגל רואה

  פקודת עבודה, לפי סדר:

  1. 🖼️  Reduce server response time
         600ms צפוי · מאמץ כבד
         TTFB גבוה הוא כמעט תמיד אחסון או היעדר page cache
  2. 📐 Size images  (מטריקה תקינה בשדה)
         400ms צפוי · מאמץ קל
```

הסדר הוא **מטריקות שנכשלות בשדה קודם**, ובתוכן לפי חיסכון חלקי מאמץ.

### שלב 3: אימות אחרי הביצוע

```bash
python scripts/speed_optimizer.py --mode verify --client example.com \
    --url https://example.com/services --live
```

משווה לבסיס, **ואז בודק שהדף עצמו שרד** — טפסים, קנוניקל, robots, ושהעיצוב
לא קרס. Remove Unused CSS היא ההגדרה שהכי שוברת עיצוב, ולכן זה לא אופציונלי.

## דגשים חשובים

**נתוני CrUX הם חלון נע של 28 יום.** מדידה ביום שאחרי העבודה עדיין מציגה את
המצב הישן. המעבדה תזוז מיד, השדה לא — והדוח אומר את זה במפורש במקום להציג
"שיפור" שהוא ארטיפקט.

**בלי נתוני תנועה אין אומדן קליקים.** `impact_clicks` יוצא 0 וההסבר אומר למה.
המצאת מספר כאן הייתה מדרגת דף איטי מול ממצא אמיתי מ-Search Console על בדיה.
עם `--traffic` (clicks_28d לדף מ-GSC) מתקבל אומדן שמרני: **3% מהקליקים, ורק
אם הדף נכשל בשדה**. דף שעובר Core Web Vitals מקבל 0 — אין לו מה להרוויח בדירוג.

**אתר קטן בלי נתוני שדה** — CrUX דורש מסה קריטית של תנועה, והרבה דפי שירות
לא מגיעים אליה. אז מתקבל fallback ברמת המקור כולו, והדוח מסמן אותו ככזה;
ואם גם הוא ריק, רמת הביטחון יורדת ל-`low` וההסבר אומר שזו סימולציה. לא
מתייחסים אליה כאילו היא מדידה.

**המרות נמדדות בנפרד.** 0.8% לכל 100ms שיפור ב-LCP, לפי המחקר של גוגל
ו-Deloitte, **וחסום ב-10%** — המחקר נמדד על שיפורים קטנים, והכפלה ליניארית על
שתי שניות הייתה מייצרת טענה של 20% ומדרגת מודל מעל נתון מדוד. מחושב רק כשיש
sessions ושיעור המרה, ומסומן בדוח כאומדן מודל.

**החיסכון הכולל אינו סכום ההזדמנויות.** CSS חוסם, תמונות לא מותאמות וסקריפט
לא ממוזער תובעים את אותן שניות של LCP. הרווחים נצברים לפי מטריקה ונחתכים
במרחק שלה מ"טוב" — דף עם LCP 4.9 שניות יכול להרוויח 2.4, לא 4.1. CLS לא
נספר במילישניות, כי הוא לא משך זמן.

**הזדמנויות מסוננות.** רק ביקורות שיש להן משמעות בוורדפרס ותרגום לפעולה.
ביקורת שגוגל מדווחת בלי אומדן זמן — TBT של תוספים, סקריפטים חיצוניים —
מתורגמת ל-30% מהסך, כי עבודת main thread אף פעם לא יורדת לאפס.

**סקריפטים חיצוניים לא מוסרים בלי לשאול.** chat, heatmaps ופיקסלים נמדדים
בהמרות. הם מופיעים בפקודת העבודה כפריט לדיון, לא כתיקון.

## קובץ התנועה

אופציונלי, ומשנה את כל התעדוף. שלוף מ-GSC Wizard קליקים לדף, ומ-GA4 סשנים
ושיעור המרה — **ברמת דף נחיתה, לא ברמת שאילתה** — ושמור:

```json
{
  "pages": {
    "https://example.com/services": {
      "clicks_28d": 1240,
      "sessions_28d": 3800,
      "conversion_rate": 0.031
    }
  }
}
```

```bash
--traffic traffic.json
```
