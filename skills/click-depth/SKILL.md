# Click Depth

מסריקה אחת יוצאים ארבעה דברים, והם לא באותה רמת ודאות. הסקיל מפריד ביניהם
בכוונה, כי דוח שמציג את כולם באותו ביטחון הוא דוח שבו הניצחונות הקלים
נבלעים יחד עם הניחושים.

| | מה זה | רמת ודאות |
|---|---|---|
| 💥 `broken` | קישור פנימי לדף שמחזיר 404 או 5xx | **עובדה.** תמיד שווה תיקון |
| 🔁 `redirect` | קישור ליעד שמפנה, ואורך השרשרת | **עובדה.** קפיצה אחת זה חוסר סדר; ארבע זה דף שאולי לא מגיעים אליו |
| 🚫 `blocked` | דף חסום או `noindex` שמקבל הופעות | **עובדה** עם סיבה ששווה לברר לפני שנוגעים |
| 🪜 `deep` | דף רחוק משלושה קליקים מדף הבית | **סימן.** הדבר הכי חלש כאן |

## למה עומק הוא לא ממצא

הכלל "שלושה קליקים" מצוטט הרבה יותר ממה שהוא נכון. עומק לא מונע גילוי —
sitemap עושה את זה — ודף במרחק חמישה קליקים שמדורג טוב הוא לא בעיה שצריך
לפתור.

מה שעומק באמת מודד זה כמה מכוח הקישורים הפנימיים מגיע לדף, וכמה רחוק גולש
צריך ללכת. לכן דף עמוק עולה לדוח **רק** כשיש לו גם **200 הופעות לפחות**,
והאומדן שלו תובע **35% מהפער בלבד** — לעומת 60% שסקיל תוכן תובע. רמת
הביטחון שלו תמיד `low`, וההסבר אומר בדיוק למה.

## הסריקה עצמה

היא רצה על אתר של לקוח בפרודקשן. כישלון כאן הוא לא דוח גרוע — הוא אתר תחת
עומס באמצע יום עבודה.

- `robots.txt` **נקרא לפני הבקשה הראשונה**, וקבוצת הכללים שלנו גוברת על `*`
- `Crawl-delay` שהאתר מבקש רק **מעלה** את ההשהיה, אף פעם לא מוריד אותה
- תקרת דפים (`--max-pages`, ברירת מחדל 400) ועצירה מוצהרת כשמגיעים אליה
- רק אותו דומיין. תת-דומיין הוא אתר אחר עם גרף קישורים משלו
- קבצים שאינם דפים — תמונות, PDF, `mailto:` — נספרים כקישורים ולא נסרקים

**`קישורים שלא מגיעים ליעד`** הוא המספר שמסכם את הכול: כמה קישורים פנימיים
באתר לא מביאים לאן שהם מתיימרים. זה המספר שמשתפר כשמתקנים.

## שרשראות — ומה צריך כדי לספור אותן

ספריית HTTP שעוקבת אחרי הפניות בעצמה מחזירה את היעד הסופי ותו לא. "הכתובת
הזו מפנה" ו"הכתובת הזו מפנה ארבע פעמים דרך שני דומיינים" הם שני ממצאים
שונים לגמרי.

`--trace` עוקב אחרי כל הפניה **קפיצה-קפיצה**, סופר את האורך, ומזהה לולאות.
זה עולה בקשה אחת לכל קפיצה, ולכן רץ רק על כתובות שכבר ידוע שהן מפנות.
בלעדיו מדווחת הקפיצה הראשונה בלבד, והסקיל אומר את זה.

## תהליך העבודה

```bash
python scripts/click_depth.py --self-check --client example.com
python scripts/click_depth.py --mode analyze --client example.com \
    --queries queries.json --trace --max-pages 400
```

`--queries` אינו חובה: העובדות ידווחו בלעדיו. דפים עמוקים ודפים חסומים
דורשים נתוני ביקוש, ובלי הקובץ הם לא ייבדקו בכלל — לא "לא נמצאו".


### תיקון: להפנות קישורים ליעד הסופי

```bash
python scripts/click_depth.py --mode plan --client example.com \
    --page https://example.com/blog/how-springs-break \
    --old https://example.com/spring-repair \
    --new https://example.com/services/springs

python -m seo_core.change_guard.plan approve plan_ab12cd34 --dir ~/.claude/seo/data/example.com/plans
python scripts/click_depth.py --mode publish --client example.com --plan plan_ab12cd34
```

טקסט הקישור נשאר, המשפט נשאר, רק היעד זז לאן שההפניה שלחה ממילא. **היעד
החדש נבדק שהוא מחזיר 200 לפני הכתיבה** — אין טעם להחליף 301 ב-404 — ונבדק
שוב אחריה.

## דגשים חשובים

**כפתור ב-Elementor לא שומר `href`.** היעד שלו יושב ב-`settings.link.url`
בעץ הווידג'טים, וחיפוש אחרי `href=` לבדו היה משאיר כל כפתור מצביע להפניה.
שניהם מטופלים.

**דף שנעצרה בו הסריקה לא נחשב עמוק.** אם הסריקה נגמרה בתקרה, העומק המרבי
שמדווח הוא של מה שנסרק — והסקיל אומר את זה במקום להציג מספר שלם.

**דף חסום עם הופעות מדווח ולא מתוקן.** בדרך כלל זה אחד משניים: `noindex`
ששרד מסביבת פיתוח, או דף שמישהו הסתיר בכוונה. שניהם שווים העלאה, אף אחד
לא שווה שינוי אוטומטי.

**קיצור הדרך לדף עמוק הוא עבודה של `internal-anchors`** — הוא יודע למצוא
משפט קיים בדף רדוד יותר ולעטוף אותו. כאן רק מסומן הדף הרדוד הקרוב ביותר.

**`gsc-crawl-checker` הוא סקיל אחר.** הוא שואל את גוגל מה לא נסרק ומגיש
כתובות לאינדוקס. כאן לא שואלים את גוגל כלום — סורקים את האתר בעצמנו ובודקים
מה **האתר** עושה לעצמו. המבדיל: *מה גוגל אומר* מול *מה נשבר במבנה*.

**פרסום חסום ללקוח שלא עבר חזרה גנרלית** של כתיבה ושחזור.
