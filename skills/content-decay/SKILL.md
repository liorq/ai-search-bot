# Content Decay

רענון דף שכבר יש לו סמכות מנצח כתיבת דף חדש כמעט תמיד. הסקיל מוצא את הדפים
האלה — ובאותה מידה חשוב, מסנן החוצה את אלה שרענון לא יעזור להם.

"הדף איבד תנועה" היא לא הוראה. שש סיבות מייצרות אותה צורה בדיוק, וארבע מהן
**לא** מטופלות בשכתוב:

| הסיווג | מה קרה | מה עושים |
|---|---|---|
| `position_loss` | הדף באמת ירד בדירוג | ✅ לרענן את התוכן |
| `serp_takeover` | מתחרה חדש נכנס לתוצאות | ✅ לקרוא את הדף שלו קודם |
| `seasonality` | המיקום נשמר, הביקוש ירד | ❌ לא לגעת. לתזמן לעונה הבאה |
| `cannibalized` | דף אחר שלנו מתחרה | ❌ מיזוג, לא שכתוב |
| `deindexed` | ההופעות צנחו כמעט לאפס | ❌ בעיית אינדוקס |
| `unclear` | אין דפוס מובחן | ❌ למדוד שוב לפני שפועלים |

**שכתוב דף שירד מעונתיות הוא עבודה שלא יכולה להצליח.** זו הסיבה שהסיווג קודם לפעולה.

`serp_takeover` דורש שם של מתחרה שנכנס — נתוני Search Console לבדם לא מבדילים
בין "ירדנו" לבין "עקפו אותנו", וטענה כזו בלי ראיה היא ניחוש.

## תהליך העבודה

### שלב 0: בדיקת תקינות

תמיד קודם — בודק `clients.json`, מפתחות וגישה ל-WordPress **לפני** שנוגעים במשהו.
בלי הרשאת כתיבה, הסקיל עובר למצב "טקסט להדבקה".

```bash
python scripts/content_decay.py --self-check --client example.com
```

### שלב 1: שליפת הנתונים

**זה החלק שלך.** כלי MCP זמינים לקלוד ולא לתהליך פייתון, אז שלוף מ-GSC Wizard
והרכב JSON במבנה הזה:

```json
{
  "property": "sc-domain:example.com",
  "current": {"range": "28d", "pages": [
    {"url": "...", "clicks": 120, "impressions": 4500, "position": 9.1,
     "queries": [{"query": "...", "clicks": 40, "impressions": 900, "position": 8.2}]}
  ]},
  "prior": {"range": "28d אשתקד", "pages": [...]},
  "site": {"clicks_pct": -0.04},
  "algorithm_updates": ["2026-08-12"]
}
```

`prior` היא **אותה תקופה אשתקד**, לא החודש הקודם — אחרת עונתיות תיראה כמו דעיכה.
ל-GSC Wizard יש 10 שנות היסטוריה, הרבה מעבר למגבלת 16 החודשים של גוגל.

### שלב 2: ניתוח

```bash
python scripts/content_decay.py --mode analyze --client example.com --gsc-data gsc.json
```

הפלט:

```
═══════════════════════════════════════════════════════
  📊 דעיכת תוכן — example.com
═══════════════════════════════════════════════════════
  דפים דועכים                14
  ניתנים לטיפול בשכתוב        6
  מגמת האתר                  -4%
  סה"כ קליקים שאבדו       1,240
───────────────────────────────────────────────────────

  📉 position_loss — 6 דפים
       180 קליקים  /services/spring-repair
           ירד 5.1 מקומות ואיבד 60% מהקליקים, בזמן שהאתר זז -4%

  🗓️  seasonality — 5 דפים
        90 קליקים  /services/ac-tune-up
           המיקום לא זז אבל ההופעות ירדו ב-70% — הביקוש ירד, לא הדף
```

הדירוג לפי קליקים **בני-השבה**, לא קליקים שאבדו: לעונתיות יש השפעה 0, כי
פעולה לא תחזיר ממנה כלום.

### שלב 3: כתיבת הפסקה

**זה החלק שלך.** קרא את הדף החי, בחר כותרת שאחריה חסרה תשובה, וכתוב פסקה
**בשפת התוכן של הלקוח** (`content_language` — לרוב אנגלית), בקול של הדף:
אורך משפט, גוף פנייה, רמת פורמליות. שמור לקובץ.

### שלב 4: תוכנית — בלי לכתוב כלום

```bash
python scripts/content_decay.py --mode plan --client example.com \
    --url https://example.com/services/spring-repair \
    --heading "Spring replacement cost" --text paragraph.txt
```

מזהה Elementor, Gutenberg או עורך קלאסי ומרכיב את השינוי בהתאם. **בדף
Elementor העריכה נכנסת לעץ הווידג'טים ולא ל-`post_content`** — כתיבה ל-
`post_content` שם מצליחה ולא משנה כלום על המסך.

מייצר `plan_<id>.md` עם ה-diff המלא. `--dry-run` עוצר כאן.

### שלבים 5–6: אישור, פרסום, מדידה חוזרת

```bash
python -m seo_core.change_guard.plan approve plan_ab12cd34 --dir ~/.claude/seo/data/example.com/plans
python scripts/content_decay.py --mode publish --client example.com --plan plan_ab12cd34
python scripts/content_decay.py --mode verify  --client example.com
```

הפרסום, בסדר הזה: מוודא אישור · משווה hash למניעת דריסה · יוצר גיבוי
**ומאמת שהוא שחזורי** · כותב · מריץ בדיקות · רושם ביומן ומתזמן 14/28/56.

## דגשים חשובים

**ירידה בדירוג לא מפעילה שחזור אוטומטי.** כשל טכני — 500, טקסט שלא רונדר,
טופס שנעלם, קנוניקל שזז — משחזר מיד. ירידה בביצועים מפיקה דוח בלבד: ירידה
28 יום אחרי שינוי היא קורלציה, לא סיבתיות.

**שחזור אוטומטי דורש גיבוי מאומת ואפס עריכות מקבילות.** חסר אחד — עצירה
והתרעה, לא ניסיון בכוח.

**מניעת דריסה לפי hash ולא `modified_gmt`**, שלא זז בחלק מעדכוני ה-meta.

**סף מינימלי:** פחות מ-10 קליקים או 100 הופעות בתקופה הקודמת — לא נבדק.
אחוזים על מספרים קטנים הם רעש שמתחזה למגמה.

**שינוי אחד לדף בכל פעם.** שישה שינויים יחד ואי אפשר לדעת מה עבד.
