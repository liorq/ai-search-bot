# Topic Cluster

`keyword-research` מוצא מילים שללקוח **אין**. הסקיל הזה עושה את העבודה
השנייה: לוקח את השאילתות שכבר מדווחות, ומחלץ מהן את המבנה שהן מרמזות עליו.

## נושאים נבנים מהדף שגוגל בחר, לא מהמילים

קיבוץ לפי מילים — "שתי השאילתות מכילות *spring*, אז זה אותו נושא" — מאחד
את `spring repair cost` עם `spring water delivery`, ומפריד את
`garage door won't close` מ-`broken torsion spring` שהן אותה כוונה בדיוק
לכל מחפש.

גוגל כבר עשה את החלק הקשה: כשהוא מדרג את **אותו דף** על שתי שאילתות, הוא
קבע שאותו תוכן עונה עליהן. ההחלטה הזו כבר נמצאת בייצוא.

שני דפים מתאחדים לנושא אחד כששאילתה אחת מדורגת על שניהם. מילים משמשות רק
כדי **לתת שם** לקלסטר אחרי שהוא קיים — שם שגוי קצת לא עולה כלום, קיבוץ
שגוי עולה את כל הניתוח.

## המפה נשמרת, ומתמזגת

```bash
python scripts/topic_cluster.py --client example.com
python scripts/topic_cluster.py --client example.com --show
```

השאילתות נמשכות לבד מ-GSC Wizard (נדרש `gsc_property` ב-`clients.json`
ו-`GSC_WIZARD_API_KEY` ב-`.env`). `--queries <קובץ>` עדיין עובד לשחזור.

הרצה חוזרת לאותו לקוח לא מייצרת מפה חדשה בלי זיכרון. היא אומרת:

```
  מאז הפעם הקודמת    נושא חדש אחד · 4 שאילתות חדשות · אחת שנעלמה ·
                     פילר אחד שהתחלף

  🆕 נושא חדש: opener-remote-programming
  ➕ spring-torsion-door: extension spring vs torsion
  ➖ cable-door-garage: cable snapped — כבר לא מופיעה
  🔀 spring-torsion-door: הפילר עבר מ-/blog/springs ל-/services/springs
```

**זהות הנושא היא השאילתות שלו, לא השם.** השם נגזר מהמילים שהשאילתות
מסכימות עליהן, ולכן הוא נודד כשהקלסטר גדל — `spring garage door` הופך
ל-`spring torsion door`. מפה שממופתחת על השם הייתה מציגה כל נושא שגדל כנושא
חדש לגמרי, ואת קודמו כנושא שנעלם. ההתאמה נעשית לפי חפיפה של 50% בשאילתות,
והשם חופשי לנדוד.

**שאילתה שהפסיקה להופיע נשמרת עם `last_seen`** ולא נמחקת. נושא שנעלם בשקט
הוא הדבר המעניין ביותר שהרצה שנייה יכולה לומר — ומחיקת השורה הייתה מוחקת
את הממצא.

## מה יוצא בהרצה

```
═══════════════════════════════════════════════════════
  🗺️  מפת נושאים — example.com
═══════════════════════════════════════════════════════
  חלון                        28d
  נושאים                      9
  ריצה                        3
  מאז הפעם הקודמת             נושא חדש אחד · 4 שאילתות חדשות · אחת שנעלמה
  עקומת CTR                   עקומה שנמדדה מהאתר עצמו על 840 שאילתות
───────────────────────────────────────────────────────

  📂 torsion spring door
       14 שאילתות · 12,400 הופעות · 640 קליקים · 2 דפים
       פילר: https://example.com/services/springs
       ⚠️  גם https://example.com/blog/spring-guide — 3,900 הופעות
       🌱 “garage door spring winding bars” — 900 הופעות במיקום 14.0,
          בלי דף משלה
```

`--self-check` מראה אם כבר קיימת מפה ללקוח, מאיזו ריצה ומתי עודכנה.
`--show` מציג את המפה השמורה בלי לבנות אותה מחדש — שימושי כשרוצים להסתכל
בלי לשלוף נתונים חדשים מ-GSC.

## שני ממצאים מבניים

| | מה קורה | התיקון |
|---|---|---|
| 🌱 `subtopic_needs_page` | שאילתה עם 300+ הופעות במיקום 10+, קבורה בדף הפילר | דף תומך ייעודי, מקושר מהפילר וחזרה |
| ⚠️ `topic_split` | דף שני מחזיק 25%+ מההופעות של הנושא | להחליט איזה דף מוביל, והשאר תומכים |

שניהם ברמת ביטחון `low` ובמאמץ `l`, בכוונה. דף חדש מתחיל בלי קישורים ובלי
היסטוריה, והאומדן מניח שהוא יגיע לעמוד הראשון — זו הנחה, לא מדידה. איחוד
נושא הוא החלטת תוכן שדורשת קריאה של שני הדפים, ולכן האומדן תובע מחצית
מהפער בלבד.

## איך נראה קובץ המפה

```json
{
  "client": "example.com",
  "updated_at": "2026-09-18T10:19:01+00:00",
  "runs": 3,
  "clusters": {
    "torsion-spring-door": {
      "label": "torsion spring door",
      "pillar": "https://example.com/services/springs",
      "created_at": "2026-07-04T09:12:00+00:00",
      "is_split": true,
      "pages": {"https://example.com/services/springs": 8500,
                "https://example.com/blog/spring-guide": 3900},
      "queries": {
        "torsion spring repair": {
          "first_seen": "2026-07-04T09:12:00+00:00",
          "last_seen": "2026-09-18T10:19:01+00:00",
          "url": "https://example.com/services/springs",
          "clicks": 210, "impressions": 3400, "position": 4.2
        }
      }
    }
  }
}
```

`first_seen` שורד כל הרצה — הוא עונה על "מתי הנושא הזה הופיע לראשונה",
שאלה שאי אפשר לשחזר בדיעבד משום ייצוא של GSC.

## דגשים חשובים

**נושא הוא לפחות שלוש שאילתות.** שתיים זה לא נושא, זה זוג שאילתות, ואין לו
אסטרטגיה.

**הסף כאן נמוך מהסף של שאר הסקילים** — 20 הופעות במקום 50. נושא נבנה מהרבה
שאילתות קטנות, וסינון של כולן היה משאיר רק את מילות הראש ומוחק את המבנה.

**`onpage-optimizer` מטפל בקניבליזציה ברמת שאילתה בודדת** — שני דפים על
מילה אחת. כאן זה ברמת הנושא: איזה דף אמור להחזיק את כל הקלסטר. המבדיל:
*שאילתה* מול *מבנה*.

**`keyword-research` מוצא מילים חדשות.** כאן אין מחקר ואין הצעות למילים
שלא קיימות — רק ארגון של מה שכבר יש. המבדיל: *מחקר* מול *קלסטר/מבנה/פילר*.

**הסקיל לא כותב לאתר.** יצירת דף תומך ואיחוד נושא הן החלטות תוכן. הוא
מייצר את המפה, את ההפרש, ואת הממצאים — והם נכנסים ל-`seo-audit-report`.
