# נוסח מעודכן לארבעת הסקילים הקיימים

ארבעת הסקילים האלה הותקנו לפני הערכה הזו, והם **לא נמצאים בריפו** — הם
יושבים ב-`~/.claude/skills/` כחלק מהחבילה המותקנת. לכן הם לא עודכנו
אוטומטית: מה שיש כאן הוא הנוסח המדויק להדבקה, בלוק `description` שלם לכל
אחד.

בלי החידוד הזה, כל סקיל חדש שנבנה כאן מתחרה על טריגרים עם סקיל קיים שכבר
תובע אותם — ובמקרה של התנגשות קלוד יטען את מי שהתיאור שלו רחב יותר, לא את
מי שמתאים יותר.

## למה זה נדרש עכשיו

| הסקיל הקיים | מה הוא בולע היום | הסקיל שנפגע |
|---|---|---|
| `keyword-research` | `SEO keywords` · "רעיונות לתוכן" | `topic-cluster` |
| `seo-monthly-report` | `דוח SEO` לבדו | `seo-audit-report` |
| `semrush-keyword-gap` | `מתחרים` לבדו | `competitor-cta` · `link-gap-prospector` |
| `gsc-crawl-checker` | "דפים שלא נכנסו לגוגל" | `click-depth` |

---

## 1. `keyword-research`

**מה משתנה:** יורדים `SEO keywords` ו"רעיונות לתוכן" כטריגרים עצמאיים,
ונוסף משפט הפרדה מפורש מול `topic-cluster`. הסקיל הזה **מוצא מילים מאפס**;
ארגון של מילים קיימות למבנה הוא לא הוא.

```yaml
description: >
  סקיל למחקר מילות מפתח עבור עסקים מקומיים בישראל. משתמש בחיפוש אינטרנט
  כדי לחקור מילות מפתח חדשות שהעסק עוד לא מדורג עליהן, לבנות וריאציות
  גיאוגרפיות (ערים + שכונות), ולהעריך נפח חיפוש. מייצר קובץ אקסל מסודר
  עם מילות מפתח, נפח חיפוש משוער, ופילוח גיאוגרפי.
  השתמש בסקיל הזה בכל פעם שמשתמש מבקש: מחקר מילות מפתח, נפח חיפוש,
  וריאציות גיאוגרפיות, על מה כדאי לכתוב, או איך אנשים מחפשים את השירות
  הזה בגוגל. גם אם המשתמש אומר בקיצור "מה כדאי לי לכתוב עליו באתר של
  העסק" או "איך אנשים מחפשים שרברב בגוגל" — הסקיל הזה צריך להיטען.
  אל תטען אותו כשהבקשה היא לארגן מילות מפתח שכבר קיימות למבנה, לקלסטרים
  או לעמודי פילר — זה `topic-cluster`.
```

## 2. `seo-monthly-report`

**מה משתנה:** יורד `דוח SEO` כטריגר עצמאי, ונוסף משפט הפרדה מול
`seo-audit-report`. המבדיל הוא *חודשי/ללקוח* מול *אודיט/טכני/תוכנית עבודה*.

```yaml
description: >
  סקיל ליצירת דוחות SEO חודשיים ללקוחות בעברית. יוצר מסמך Word (.docx)
  מקצועי עם יישור RTL, נתוני Google Search Console, ניתוח Sitemap, סיכום
  העבודה שבוצעה החודש, ותוכנית להמשך. הכתיבה חמה, אישית ומשכנעת — היא
  מיועדת ללקוח, לא לצוות.
  השתמש בסקיל הזה בכל פעם שמשתמש מבקש: דוח חודשי ללקוח, סיכום חודשי,
  עדכון חודשי לעסק, מה עשינו החודש, או מסמך שמסכם עבודת SEO שבוצעה. גם
  אם המשתמש כותב בקיצור "תעשה דוח ל-example.com" או "אותו דבר לאתר הזה"
  — הסקיל הזה צריך להיטען.
  אל תטען אותו כשהבקשה היא אודיט, דוח טכני, תוכנית עבודה לצוות או "מה
  לתקן קודם" — זה `seo-audit-report`.
```

## 3. `semrush-keyword-gap`

**מה משתנה:** `מתחרים` לבדו מפסיק להיות טריגר. הסקיל נטען רק כשמופיע גם
ההקשר של keyword gap, KD, או רשימת דומיינים.

```yaml
description: >
  Automates SEMrush Keyword Gap analysis for large lists of competitor
  domains. Downloads low-difficulty keywords (KD ≤ 5) in batches of 5,
  saves to Desktop/מילות מפתח/, and merges everything into a clean
  deduplicated Excel with keyword | KD | volume columns.
  השתמש בסקיל הזה כשהמשתמש מזכיר: keyword gap, פערי מילות מפתח מול
  מתחרים, KD, רשימת דומיינים של מתחרים, מיזוג CSV של SEMrush, או הרצה
  מחדש של האוטומציה. גם אם המשתמש רק שולח רשימת דומיינים בלי להסביר —
  הצע להריץ עליהם Keyword Gap.
  אל תטען אותו כשהבקשה על מתחרים היא: למה הם ממירים ואיך נראה ה-CTA
  שלהם (`competitor-cta`), או מי מקשר אליהם (`link-gap-prospector`).
```

## 4. `gsc-crawl-checker`

**מה משתנה:** נוסף משפט הפרדה מול `click-depth`. שניהם עוסקים בדפים שלא
מאונדקסים, וההבדל הוא **את מי שואלים**: זה שואל את גוגל דרך GSC, וזה סורק
את האתר ובודק מה האתר עושה לעצמו.

```yaml
description: >
  בודק אילו עמודים מתוך sitemap לא נסרקו או לא מאונדקסים בגוגל, באמצעות
  Google Search Console דרך Playwright עם פרופיל Chrome אמיתי. מציג דוח
  מסודר, שואל את המשתמש אילו לינקים לשלוח לסריקה, ושומר מעקב כדי לא
  להגיש שוב לינקים שכבר הוגשו במשך שבוע.
  השתמש בסקיל הזה בכל פעם שמשתמש מזכיר: בדיקת סריקה, sitemap, לינקים
  שלא נסרקו, עמודים שלא מאונדקסים, GSC, Google Search Console, שליחה
  לאינדוקס, URL Inspection, בדיקת כיסוי, request indexing, או סרצ'
  קונסול. גם אם המשתמש אומר בקיצור "תבדוק את המפה של example.com" או
  "שלח לסריקה" — הסקיל הזה צריך להיטען.
  אל תטען אותו כשהבקשה היא לסרוק את האתר בעצמנו ולמצוא 404, שרשראות
  הפניה או עומק קליקים — זה `click-depth`. המבדיל: *מה גוגל אומר* מול
  *מה נשבר במבנה*.
```

## איך מחליפים

לכל סקיל, ב-`~/.claude/skills/<שם-הסקיל>/SKILL.md`:

1. פתח את הקובץ
2. החלף את בלוק `description:` שב-frontmatter בנוסח שכאן — **רק אותו**,
   שורת `name:` נשארת כפי שהיא
3. שמור

ההחלפה לא נוגעת בקוד של הסקילים ולא בסקריפטים שלהם, רק בשורות שמחליטות
מתי הם נטענים. אחריה כדאי לבדוק את ההפרדות הקריטיות:

| נסה לומר | אמור להיטען |
|---|---|
| "תעשה דוח חודשי ל-X" | `seo-monthly-report` |
| "תעשה אודיט ל-X" | `seo-audit-report` |
| "מחקר מילות מפתח לשרברב" | `keyword-research` |
| "תבנה לי מפת נושאים" | `topic-cluster` |
| "מה לא נסרק ב-X" | `gsc-crawl-checker` |
| "יש לי 404 באתר" | `click-depth` |
| "keyword gap מול המתחרים" | `semrush-keyword-gap` |
