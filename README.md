# ערכת סקילים ל-SEO

שכבה שיושבת מעל הכלים הקיימים — GSC Wizard, Localo, Clarity, DataForSEO, Semrush — ועושה
את מה שהם לא עושים: מחליטה מה לשנות, כותבת את הטקסט, מבצעת באתר, מודדת אם זה עבד,
ויודעת לשחזר.

**המטרה היא ביצוע בטוח, לא עוד רשימת המלצות.**

## העיקרון

> ה-MCPs נותנים נתונים ואבחון. הסקילים נותנים החלטה, ביצוע, ואימות.

אף סקיל לא כותב קוד שמשכפל משהו שקונקטור כבר עושה טוב.

## שני החוקים שאוכפים את זה בקוד

**1. אין ממצא בלי ראיות ובלי פעולה.**
`Finding` מסרב להיווצר אם חסרים `evidence`, `action`, `baseline`, `impact_basis` או
`confidence_reason`. זו אכיפה ב-`__post_init__`, לא הנחיה סגנונית — ככה אי אפשר לכתוב
סקיל שמחזיר "כדאי לשפר את התוכן".

**2. ירידה בדירוג לא מפעילה שחזור אוטומטי.**
תקלה טכנית (500, HTML שבור, טופס מת) → שחזור אוטומטי, אבל רק אם יש גיבוי שאומת כשחזורי
ואין עריכה מקבילה. ירידה בביצועים → דוח בלבד; ירידה 28 יום אחרי שינוי היא קורלציה,
לא סיבתיות. מצב `inconclusive` קיים במפורש.

## התקנה (חד-פעמי)

**macOS / Linux**

```bash
git clone <repo> && cd ai-search-bot
pip install -r requirements.txt
./install.sh
```

**Windows / PowerShell** — `&&` לא נתמך ב-PowerShell 5, ולכן כל פקודה בשורה
נפרדת, ו-`install.sh` הוא סקריפט bash שלא ירוץ שם:

```powershell
git clone <repo>
cd ai-search-bot
py -3 -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

`install.ps1` עושה את אותו הדבר, עם ההתאמות שהפלטפורמה דורשת: מאתר את
הפייתון דרך ה-launcher, מגביל את ההרשאות לתיקיית הסודות דרך ACL במקום
`chmod`, ויוצר junction בשולחן העבודה במקום symlink.

ההתקנה מעתיקה את `seo_core` ל-`~/.claude/seo_core/`, את הסקילים ל-`~/.claude/skills/`,
ויוצרת `~/.claude/seo/` עם `.env` ו-`clients.json` — שניהם **מחוץ לריפו** ולא נדרסים בהתקנה חוזרת.

אחר כך:

1. מלא את `~/.claude/seo/.env` לפי `.env.example`
2. השלם את `~/.claude/seo/clients.json` לפי `clients.example.json`
3. הרץ כל סקיל פעם ראשונה עם `--self-check`

### איפה יושבים המפתחות

```
~/.claude/seo/
├─ .env            מפתחות API וסיסמאות WordPress   (chmod 600)
├─ clients.json    רישום הלקוחות
└─ data/<לקוח>/    ממצאים, תוכניות, גיבויים, יומן
```

ההתקנה יוצרת **קיצור דרך בשולחן העבודה** בשם `SEO-Keys` שמצביע לשם — נוחות
בלי להזיז את הקבצים עצמם לתיקייה שמסונכרנת לענן. ב-Windows זה junction,
ב-mac ולינוקס symlink.

להזיז באמת: `SEO_HOME=/path/to/dir`. זה מזיז את שלושתם יחד, וכל `--self-check`
מדפיס איפה הם יושבים ומתריע אם המקום בעייתי — תיקייה מסונכרנת (iCloud, Dropbox,
OneDrive), שולחן עבודה, מאגר git, או `.env` שקריא למשתמשים אחרים במחשב —
הבדיקה האחרונה רצה רק היכן שיש הרשאות POSIX, כי ב-NTFS יש ACL ופייתון מדווח
שם 0o666 קבוע לכל קובץ.

**שולחן העבודה הוא לא מקום לסודות.** ברוב המחשבים הוא מסונכרן לענן, והוא מה
שרואים בכל שיתוף מסך.

### סיסמת אפליקציה ל-WordPress

לכל לקוח: לוח בקרה → משתמשים → הפרופיל → Application Passwords → צור חדשה.
השם שתיתן למשתנה ב-`.env` חייב להתאים ל-`auth_env` של אותו לקוח ב-`clients.json`.

## בדיקות

```bash
python3 -m pytest tests/ -q
```

הבדיקות רצות בלי רשת ובלי עלות API. מה שנבדק:

- **חוזה ה-`Finding`** — שכל ניסוח גנרי באמת נדחה
- **דירוג** — שהמרות גוברות על קליקים, ושרמת ביטחון נמוכה מקבלת הנחה
- **רישום הלקוחות** — שלקוח מוגדר חלקית מסרב להיטען
- **סודות** — שהסורק תופס סיסמה בקוד ומתעלם מקריאה תקינה מהסביבה
- **שחזור** — ש-`safe_to_auto_rollback` דורש גיבוי מאומת ואין עריכה מקבילה
- **hash** — שזיהוי עריכה מקבילה תופס גם שינוי ב-meta בלבד, ש-`modified_gmt` מפספס
- **החזרה הגנרלית** — שכתיבה שמוחזרת כ-200 ולא משנה כלום נתפסת, ושחזור שנכשל
  מסומן כבלתי ניתן לניסיון חוזר
- **מהירות** — שנתוני שדה גוברים על ציון המעבדה, ושדף שעובר CWV לא מקבל אומדן קליקים
- **מיגרציה** — שארכיון קטוע נתפס לפני ייבוא, שכשל באמצע ייבוא מוביל לשחזור ולא
  לניסיון שני, ושמדיה לא נמחקת כדי להיכנס ל-500MB
- **טייטלים** — שאותה ספירת תווים נכנסת בגופן אחד ונחתכת באחר, שזנב ארוך בעמוד
  השני לא מוריד את ה-CTR המדוד, ושהצעה שמורידה מילה שמביאה קליקים נדחית
- **סריקה** — ש-robots.txt נכבד, שקישור פנימי שבור נתפס עם מי שמקשר אליו,
  ושתפריט לא נספר כהמלצה עריכתית
- **איחוד ממצאים** — שארבעה תיקונים על אותו דף לא מסתכמים ליותר ממה שהדף
  יכול להביא, ושתקלה ודאית לא נדחית לטובת אומדן
- **מדידת המרות** — שהתקנת GA4 תקינה, שמזכירה את המזהה פעמיים, לא מדווחת
  כספירה כפולה, ושמכולת GTM לא מקבלת תעודת כשרות
- **מפת נושאים** — שמילים משותפות לא מאחדות שני נושאים, ושנושא שגדל ושינה
  שם לא נספר כנושא חדש
- **עדכוני אלגוריתם** — שדף שירד לבד לא נתלה בעדכון ליבה, ושחלון מאוחר
  מהרשימה המובנית מדווח כלא-ידוע ולא כ"נקי"
- **הריפו עצמו** — שסורק הדליפות רץ על כל הקבצים, כולל `tests/`, ולא מוצא כלום

בכל סקיל, בנוסף: `--self-check` לפני נגיעה בכלום, ו-`--dry-run` שמייצר תוכנית ו-diff
מלאים בלי לכתוב שום דבר.

## החזרה הגנרלית

לפני כתיבה ראשונה לאתר של לקוח, הוא עובר דריל אחד: פסקת סימון נכתבת לדף
ב-Staging, מאומתת, ואז משוחזרת — והדף חייב לחזור לאותו hash בדיוק.

```bash
python3 -m seo_core.wp.rehearsal --client example.com
python3 -m seo_core.wp.rehearsal --client example.com --status
```

**`content-decay` מסרב לפרסם ללקוח שלא עבר את זה**, ותוקף הדריל 180 יום —
תוספים והרשאות משתנים. הדריל הוא גם מה שתופס את הכישלון שנראה כמו הצלחה:
כתיבה שמחזירה 200 ולא משנה כלום.

### מה חסום, ולמה

שישה סקילים מהתוכנית לא נבנו, וכולם מאותה סיבה: הם צורכים מקור נתונים
שאינו מחובר לסביבה הזו, ולכתוב אותם עכשיו פירושו לכתוב מול ממשק שלא נראה.

| הסקיל | מה חסר |
|---|---|
| `clarity-gsc` | Microsoft Clarity — טוקן לכל לקוח |
| `competitor-cta` · `link-gap-prospector` | DataForSEO / Semrush |
| `gbp-local-optimizer` · `reviews-engine` | Localo MCP, וגם החלטה אם מותר לכתוב ל-GBP |
| `lead-quality-loop` | מקור לידים מה-CRM של הלקוח |
| `ai-visibility` | חלקו אפשרי מהסריקה, חלקו דורש שאילתות למודלים |

`sources/ga4.py` נשאר ריק מאותה סיבה — `conversion-tracking-audit` עובד
בינתיים מה-HTML ומהשוואת קליקים מול סשנים, בלי גישת API.

סדר הבנייה: תשתית → פיילוט אחד מלא → בדיקות שחזור → מהירות → מיגרציה → הרחבה.
המטרה היא להוכיח שתהליך אחד עובד בבטחה מקצה לקצה לפני שמרחיבים.
